# ДОКУМЕНТАЦИЯ ПО РАСЧЕТАМ В СИСТЕМЕ МЕЖФИЛИАЛЬНЫХ ПЕРЕМЕЩЕНИЙ

## 📊 ОСНОВНЫЕ РАСЧЕТЫ ОБОРАЧИВАЕМОСТИ

### 1. Базовый расчет оборачиваемости
**Файл**: `turnover_report_generator.py`
**Функция**: `calculate_warehouse_turnover_report()`

#### Формула оборачиваемости:
```
ОБОР_ДН = (Остаток * Период) / Продажи
где Период = 30 дней (месяц)
```

#### 🔍 ОТКУДА БЕРЕТСЯ ПЕРИОД 30 ДНЕЙ:

**Источник периода:** JSON файлы продаж содержат поле с датами периода
```json
{
  "НачалоПериода": "2025-06-01",
  "КонецПериода": "2025-06-30"
}
```

**Логика определения:**
- Анализируются фактические даты в JSON файлах продаж
- Чаще всего это месячный период (30 дней)
- В коде **хардкодится** значение `30` для стандартизации расчетов
- Это означает, что все расчеты приведены к **месячной базе**

#### Пример расчета:
- Остаток по категории: 1,000,000 ₸
- Продажи за период: 500,000 ₸
- Оборачиваемость = (1,000,000 * 30) / 500,000 = 60 дней

#### Обработка особых случаев:
- **Если продажи > 0**: Нормальный расчет по формуле
- **Если продажи = 0 и остаток = 0**: Оборачиваемость = 0 дней
- **Если продажи = 0 и остаток > 0**: Оборачиваемость = 9999 (∞) - товар не продается

### 2. Расширенный расчет по себестоимости
**Файл**: `turnover_report_generator.py`
**Функция**: `generate_cost_based_turnover_report()`

#### Отличие от базового расчета:
- Используется **себестоимость продаж** вместо выручки
- Остатки считаются по **себестоимости**
- Добавляются **проценты** от общих сумм

#### Формула та же:
```
ОБОР_ДН = (Остаток_по_себестоимости * 30) / Продажи_по_себестоимости
```

#### Расчет процентов:
```python
sales_percent = (продажи_категории / общие_продажи) * 100
stock_percent = (остаток_категории / общий_остаток) * 100
```

## 🏢 РАСЧЕТЫ МЕЖФИЛИАЛЬНЫХ ПЕРЕМЕЩЕНИЙ

### 1. Анализ ADS (Average Daily Sales)
**Файл**: `multi_branch_analyzer.py`

#### Расчет ADS по товару:
```python
total_revenue = sum(продажи_товара_по_всем_филиалам)
days_in_period = 30  # ВСЕГДА 30 дней (стандартизовано)
ADS = total_revenue / days_in_period
```

#### 🔍 ОТКУДА ПЕРИОД В ADS:
**Период ADS = 30 дней** - это константа в системе, означает:
- Все ADS приведены к месячной базе
- Продажи за любой период пересчитываются на 30 дней
- Например: если данные за 15 дней → ADS = (выручка_15_дней / 15) * 30

### 2. Нормы запасов
**Файл**: `multi_branch_analyzer.py`
**Функция**: `calculate_stock_norms()`

#### Расчет нормы запаса:
```python
# Для каждого товара по филиалам
stock_norm_days = 30  # дни запаса (может варьироваться)
recommended_stock = ADS * stock_norm_days
```

#### 🔍 ОТКУДА БЕРУТСЯ ДНИ ЗАПАСА:
**Дни запаса** - это **бизнес-параметр**, который может быть:
- 7-14 дней - для быстрооборачиваемых товаров
- 30 дней - стандартный месячный запас
- 60-90 дней - для медленнооборачиваемых или сезонных товаров

**В текущей системе** чаще всего используется 30 дней как **стандартная норма**.

### 3. Анализ возможностей перемещений
**Файл**: `multi_branch_analyzer.py`

#### Условия для перемещения:
1. **Товар продается в нескольких филиалах**
2. **Существует значительная разница в ADS между филиалами**
3. **У одних филиалов избыток, у других дефицит**

#### Расчет приоритета перемещения:
```python
# Разница в ADS между филиалами
ads_difference = max_ads_branch - min_ads_branch

# Приоритет зависит от:
priority = {
    'Высокий': ads_difference > 1000,
    'Средний': 500 < ads_difference <= 1000,
    'Низкий': ads_difference <= 500
}
```

**Файл**: `hierarchical_movement_system.py`

if current_stock < (ads * min_days_stock):
    # Дефицит - нужно пополнение
    recommendation_type = 'пополнение_дефицита'

## 🔍 АЛГОРИТМ ИЗВЛЕЧЕНИЯ КАТЕГОРИЙ

### 1. Извлечение из JSON данных
**Файл**: `json_category_extractor.py`

#### Структура пути категорий:
```
Путь: "Кромочные материалы/19*0,8мм ПВХ/Кромка ПВХ Польша"
```

#### Логика извлечения:
```python
def extract_categories_from_path(self, category_path: str):
    parts = category_path.split('/')
    
    return {
        'main_category': parts[0] if parts else 'Без категории',  # Главная
        'sub_category': parts[1] if len(parts) > 1 else '',       # Подкатегория
        'detail_category': parts[2] if len(parts) > 2 else '',    # Детальная
        'full_path': category_path                                 # Полный путь
    }
```

### 2. ABC анализ по категориям
**Файл**: `json_category_extractor.py`

#### Расчет ABC групп:
```python
# Сортировка категорий по выручке (убывание)
sorted_categories = sorted(categories, key=lambda x: x['revenue'], reverse=True)

# Расчет накопительного процента
cumulative_percent = 0
for category in sorted_categories:
    cumulative_percent += category['percent_of_total']
    
    if cumulative_percent <= 80:
        category['abc_group'] = 'A'
    elif cumulative_percent <= 95:
        category['abc_group'] = 'B'
    else:
        category['abc_group'] = 'C'
```

## 🎯 КЛЮЧЕВЫЕ КОНСТАНТЫ

### Временные периоды:
- **Период расчета ADS**: 30 дней (стандартизован)
- **Период оборачиваемости**: 30 дней (стандартизован)
- **Минимальный запас**: 7-14 дней (бизнес-параметр)
- **Максимальный запас**: 60-90 дней (бизнес-параметр)

### 📅 ВАЖНО: ОПРЕДЕЛЕНИЕ ФАКТИЧЕСКОГО ПЕРИОДА

#### Как система определяет период из JSON:
```python
# В JSON файлах есть даты периода:
"НачалоПериода": "2025-06-01"
"КонецПериода": "2025-06-30"

# Фактический период = 30 дней
actual_days = (end_date - start_date).days
```

#### Почему используется константа 30:
1. **Стандартизация** - все расчеты приводятся к единой базе
2. **Сопоставимость** - можно сравнивать разные периоды
3. **Простота** - не нужно каждый раз вычислять количество дней
4. **Бизнес-логика** - месяц = стандартная единица планирования

#### Если фактический период отличается от 30 дней:
```python
# Система НЕ корректирует автоматически
# Все равно использует формулу с 30 днями
# Это может привести к неточностям при коротких периодах
```

### Пороговые значения:
- **Высокий приоритет перемещения**: разница ADS > 1000
- **Минимальная сумма для анализа**: 1000 ₸
- **Бесконечная оборачиваемость**: 9999 дней (нет продаж)

### Коды приоритетов:
- **Высокий**: Критический дефицит или большой избыток
- **Средний**: Умеренные отклонения от нормы
- **Низкий**: Незначительные корректировки
